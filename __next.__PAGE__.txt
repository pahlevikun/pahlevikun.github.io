So, what’s Builder Design Pattern? Based on some article from Internet, Builder Design Pattern is a way to builds a complex object using simple objects and using a step by step approach or usually call chaining. This type of design pattern comes under creational pattern as this pattern provides one of the best ways to create an object.</p><p>I use this Builder Design Pattern in some of my open source project in github (you can visit <a href="https://github.com/pahlevikun">my github profile</a> here), and I use it for re-write (or revamp) the new Midtrans Mobile SDK. Please allow me to use my works on new Midtrans SDK as example case for this article. For your information, you can find it from this <a href="https://github.com/veritrans/veritrans-android/tree/feature/revamp">link</a> as it’s open source so you can freely contribute. Until now, I think the advantages of using Builder Pattern is :</p><ol><li>You can easily maintain your code because you only has 1 Constructor and 1 Builder for large property in an instance class. Why? Because Builder Design Pattern not use general method like multiple Constructor with some combinations of multiple parameter or nested objects, Builder Design Pattern use inner class as Builder and pass it to main class as object.</li><li>Builder Pattern has flexible shape when chaining object, it can prevent your code from any error as user will know what they are passing to the SDK because of specific setter for each property. It can contain mandatory property and also optional property, for example you can see code below in Java :</li></ol><pre>MidtransSdk<br>        .<em>builder</em>(<br>                CONTEXT_AS_MANDATORY,<br>                CLIENT_KEY_AS_MANDATORY,<br>                BASE_URL_AS_MANDATORY<em><br>        </em>)<br>        .setLogEnabled(true) // This is optional property<br>        .setEnvironment(environment) // This is optional property<br>        .setApiRequestTimeOut(60) // This is optional property<br>        .build(); // Return the instance you set as object</pre><p>So, how to convert traditional way using Builder Design Pattern? The Builder Design Pattern is solution, just adding static inner class that return itself until finish with build, then send it to main class constructor then retun it. You can make your object class like code below :</p><pre><strong>public class </strong>Information {<br>    <strong>private </strong>String <strong>name</strong>;<br>    <strong>private </strong>String <strong>phone</strong>;</pre><pre><strong>    public</strong> Information(<br>            String <strong>name</strong>,<br>            String <strong>phone</strong>) {<br>        this.<strong>name</strong> = <strong>name</strong>;<br>        this.<strong>phone</strong> = <strong>phone</strong>;<br>    }</pre><pre>    // Here&#39;s come the setter and getter</pre><pre>    public String getName() {<br>        return name;<br>    }<br>    public String getPhone() {<br>        return phone;<br>    }</pre><pre><strong>    public static class </strong>Builder {<br>        <strong>private </strong>String <strong>name</strong>;<br>        <strong>private </strong>String <strong>phone</strong>;</pre><pre><strong>        public</strong> Builder(String <strong>name</strong>) {<br>            this.<strong>name</strong> = <strong>name</strong>;<br>        }</pre><pre>        <strong>public</strong> Builder setPhone(String phone) {<br>            this.<strong>phone</strong> = <strong>phone</strong>;<br>            <strong>return this;</strong><br>        }</pre><pre>        <strong>public</strong> Information build() {<br>            <strong>return new</strong> Information(<br>                 this.<strong>name</strong>,<br>                 this.<strong>phone</strong>)<br>        }</pre><pre>    }<br>}</pre><p>You know, Builder Design Pattern have some weakness beside of it’s advantages.
